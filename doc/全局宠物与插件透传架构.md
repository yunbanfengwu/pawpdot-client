# PawPdot 全局宠物与 Harness 插件透传架构

2026-11-12

## 结论

宠物和灵动岛都应属于 PawPdot 外壳的全局能力。DeepSeek Harness 负责会话、模型、工具、任务和插件业务。外壳负责所有窗口都能看到的界面、宠物当前状态、全局活动、音频通话状态、主题和安全边界。

当前工程已经有一部分正确基础：

- backend/desktop-chrome.cjs 创建外壳叠加层，并管理灵动岛视图。
- backend/workbench-preload.cjs 给 Harness 页面暴露受限的 pawpdotIsland API。
- Harness 插件通过 shell.overlay、main 和 conversation.hero.frame 参与工作台页面。
- 应用窗口通过 backend/app-preload.cjs 使用受限的灵动岛接口。
- frontend/branding/ 目前把首页宠物位置留在 Harness 的 pawpdot.home.pet 插槽。

这个插槽可以保留为兼容入口。正式的宠物本体、选择状态、资源缓存和跨窗口状态应迁移到外壳服务。

## 两层职责

### PawPdot 外壳

- 渲染首页宠物、宠物浮动操作和宠物详情。
- 管理宠物身份、当前装扮、动作状态、音频表现和领养目录缓存。
- 管理实时电话的麦克风、扬声器、电平和通话生命周期。
- 通过灵动岛显示通话、派活、执行进度和其他全局活动。
- 在多个 PawPdot 窗口之间同步宠物与活动状态。
- 在外壳层验证插件请求的来源、能力、窗口和当前用户上下文。

### DeepSeek Harness

- 提供会话目录、会话创建、提示提交、工具调用和执行结果。
- 运行 DSH 插件，提供模型、自动化、插件市场和会话内业务。
- 通过明确的外壳桥接请求宠物做动作、开始通话、创建执行会话或发布全局活动。
- 不直接操作 Electron 的 BrowserWindow、WebContentsView、麦克风或全局宠物资源。

外壳不应该把 Harness 的 DOM 当作自己的界面。Harness 页面关闭、刷新或切换页面时，宠物和灵动岛仍然保留。

## Harness 插件如何透传到外壳

透传走四段路径：

    DSH 插件
      → workbench-preload.cjs 的受限 pawpdot bridge
      → Electron main 进程验证来源与身份
      → desktop-chrome / shell pet service
      → 全局宠物或灵动岛

建议的桥接命名空间如下：

    window.pawpdot.pet.getState()
    window.pawpdot.pet.setAction({ action: 'wave', source: 'plugin-id' })
    window.pawpdot.pet.openAdoption()
    window.pawpdot.pet.speak({ text, source: 'plugin-id' })
    window.pawpdot.pet.onState(callback)

    window.pawpdot.activity.publish({
      id, pluginId, pageId, title, detail, status, progress
    })

桥接接口必须只接受结构化数据。插件只能使用被声明和授权的能力，不能传入任意 JavaScript、HTML、文件路径或 Electron 对象。每个请求保留 pluginId、窗口来源、会话 ID、工作空间 ID 和请求 ID。窗口关闭、插件卸载、会话切换和请求超时都要清理关联状态。

pawpdotIsland 当前已经是这个模式的早期版本。宠物桥应沿用同一套来源校验和生命周期，而不是再开一套插件直连通道。

## 社区换皮肤插件能否全局应用

可以，但要区分插件类型。

### 可以全局应用

- 颜色、字体、圆角、背景、材质和主题令牌。
- 宠物皮肤、服装、饰品和动作包。
- 宠物行为配置，例如待机动作、说话动作和通话表情。
- 全局活动类型和灵动岛展示数据。
- 通过版本化清单声明的资源包。

这类插件由 Harness 发现和管理，外壳读取经过验证的 manifest 和资源包。外壳只应用允许的主题令牌、宠物资源和动作数据。

### 不能直接全局应用

- 只修改 Harness 内部 DOM 的换肤插件。
- 依赖某个 Harness React 组件私有 class 的样式。
- 注入任意脚本、读取其他插件数据或直接调用 Electron API。
- 假设自己控制工作台顶部、灵动岛或所有窗口的插件。

这类插件仍然只能影响 Harness 页面。若想成为全局能力，需要增加一个明确的 pawpdot-shell 适配层，由插件提供主题、资源和能力声明，外壳根据协议重新渲染。

## 全局皮肤协议

建议插件清单声明：

    {
      "id": "community.pet-skin.example",
      "version": "1.0.0",
      "target": "pawpdot-shell",
      "capabilities": ["pet.skin", "pet.actions", "theme.tokens"],
      "resources": {
        "petPack": "petpacks/example.petpack",
        "theme": "theme.json"
      },
      "compatibility": {
        "shellApi": "^1.0",
        "renderer": ["threejs-glb-v1"]
      }
    }

安装流程由 Harness 插件管理器完成，外壳只接收已经过来源、版本、大小、摘要、格式和授权检查的资源。启用、停用和升级通过主进程协调，保留当前宠物和灵动岛状态，不能因为换肤刷新而丢失会话。

## 宠物交互的统一状态

外壳维护一个宠物状态机，Harness 和 DSH 插件只发意图：

    idle → listening → planning → speaking → task-accepted → idle

状态机负责：

- 点击宠物后显示打电话、查看任务和领养等操作。
- 通话期间让宠物聆听、回应和播放音频频谱。
- 语音明确派活后创建独立执行会话。
- 只在收到真实受理回执后显示已派活。
- 将任务状态发布给外壳灵动岛。
- 在执行会话完成、失败或需要确认时更新全局活动。

Harness 插件可以提供执行能力，不能自行伪造「已完成」或绕过外壳权限。

## 迁移顺序

1. 保留现有 pawpdotIsland 桥和 pawpdot.home.pet 兼容插槽。
2. 在外壳主进程增加 PetService，集中管理宠物资源、状态和窗口广播。
3. 将首页宠物从 Harness 渲染插件迁移到外壳 overlay。Harness 首页只保留对话内容和能力请求。
4. 将实时电话状态和频谱数据接入 PetService，灵动岛只订阅外壳状态。
5. 为 DSH 插件增加 pawpdot.pet 能力声明和受限桥接。
6. 让社区换肤插件先适配主题令牌和宠物包，再允许它申请全局能力。
7. 最后移除旧的 Harness 首页宠物渲染，保留兼容期和回退界面。

PawPdot 的首页因此保持全局一致。DeepSeek Harness 仍然是执行和插件业务中心，外壳成为宠物、灵动岛和跨窗口体验的唯一呈现层。

## dsh-pet 参考

社区的 dsh-pet 采用「播放器、状态服务、位置接口」组合。透明动画播放器在 DSH 页面中渲染，宿主状态通过 Cordis 服务提供给同页插件，另有本机 HTTP 接口给跨进程调用。它公开当前宠物的归一化位置和朝向、当前动画播放进度、完整状态快照、菜单点击事件、工作状态和语音接口。网页 overlay、Electron 透明窗口和独立模式共用状态模型。 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet)

PawPdot 采用同一分层思路，但角色播放器使用 AuDoter 已有的 Three.js GLB 播放器。角色渲染放在 Harness 首页的 pawpdot.home.pet 插槽，因此能跟随首页布局。外壳负责窗口、持久状态和跨窗口同步。Harness 通过 pawpdot.pet bridge 发送动作和业务意图。后续可以补齐 dsh-pet 这类状态接口：

- pose(petId) 返回归一化位置和朝向。
- progress(petId) 返回动作、时间、时长、暂停和缓冲状态。
- getState() 返回带版本号的只读快照。
- onEvent() 提供点击、菜单、工作状态和通话事件。

这套接口让宠物动作、聊天、派活、灵动岛和第三方 DSH 插件共享同一状态来源。Three.js 负责骨骼蒙皮和动作混合。Cocos 作为后续旅行场景播放器接入同样的状态协议，不再让每个引擎各自定义一套宠物业务接口。
